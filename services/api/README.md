# Backend API

Technology: Python + FastAPI.

The API now contains the completed Phase 1 data/access foundation and the first Phase 2 evidence-capture slice.

## Current capabilities

- `GET /health` liveness;
- `GET /health/ready` database readiness;
- versioned Alembic migrations;
- persisted Officer / Supervisor / Admin users;
- Argon2 password hashing and JWT authentication;
- officer-owned inspection lifecycle;
- supervisor/admin inspection read access;
- append-only inspection audit events;
- authenticated package-image upload for draft inspections;
- JPEG/PNG/WebP content verification;
- SHA-256 image checksum and dimension metadata;
- protected capture listing and original-content retrieval;
- local filesystem media adapter behind a replaceable storage dependency.

OCR, preprocessing derivatives, quality scoring, Legal Metrology rule execution, reports and offline sync are not represented as working yet.

## Local setup

From `services/api`:

```bash
python -m venv .venv
# activate the virtual environment
pip install -e ".[dev]"
```

Create a local `.env` from the repository `.env.example`.

Apply migrations:

```bash
alembic upgrade head
```

Create a prototype officer account:

```bash
python -m app.cli.create_user \
  --email officer@example.test \
  --name "Demo Officer" \
  --role officer
```

Run the API:

```bash
uvicorn app.main:app --reload
```

Run tests:

```bash
pytest
```

## Evidence-storage rule

Original uploaded images are treated as immutable evidence. Later preprocessing must create derivatives rather than overwrite the original bytes/checksum.

Client filenames are display metadata only. Filesystem/object keys are generated by the server.

## Supported capture formats

The first Phase 2 slice accepts decoded JPEG, PNG and WebP images. Client MIME type and filename extension are not trusted as proof of format.

## Database rule

PostgreSQL remains the production target. SQLite in tests is isolated test infrastructure.

Schema changes must use Alembic migrations.

## Authentication rule

There is no public registration route. Prototype users are provisioned administratively.

## Lifecycle rule

Image upload is allowed only while an officer-owned inspection is still a draft. Finalization remains intentionally unavailable until the later officer-review/report phase.
