# Phase 1 API Error Convention

Domain failures use a stable machine-readable shape:

```json
{
  "error": {
    "code": "inspection_not_found",
    "message": "Inspection not found."
  }
}
```

## Rules

- `code` is stable and intended for client logic.
- `message` is concise, human-readable text.
- HTTP status still carries the protocol meaning.
- Request-validation errors generated by FastAPI/Pydantic remain framework validation responses for now.
- Domain errors must not leak stack traces, SQL details, secrets, or internal exception text.

## Initial domain statuses

- `404` — requested domain record does not exist.
- `409` — requested lifecycle action conflicts with the current resource state.

More error types should be added only when a real use case requires them.
